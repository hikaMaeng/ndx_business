## The rule

The model is not the signed-in person's choice. A business decides what its
people's agents run on, the same way it decides what skills they get — and a
per-user picker would make "which model wrote this" unanswerable from the org
chart.

```
the project's organisation → its parent → … → the root
    ↳ stop at the first one with a model attached
no organisation, or nothing anywhere up the chain
    ↳ the deployment's default model
```

Searching **upwards** is what makes a parent's choice a default its children
inherit and may replace. Downwards or sideways would make it something else.

## Registered

`qwen3.8-27b-mlx` is the deployment default. Its capabilities were measured
against the running endpoint rather than assumed:

| | | |
| --- | --- | --- |
| context | **131072** | what LM Studio loaded; the model's own maximum is 262144 |
| `reasoning` | true | the endpoint returns `reasoning_content` as its own field |
| vision | true | shown a red square, answered "Red" |
| sampling | temp 0.3, top_p 0.9, top_k 20, min_p 0, repeat 1.05 | see below |

**temperature 0.3** is below the Qwen3 family's chat defaults on purpose: an
agent that answers the same question with a different shell command each time is
one nobody can debug, and a retry that varies teaches nothing. Not lower, and
not greedy — this model thinks, and Qwen3 is documented to degrade into
repetition when decoding is made deterministic.

**repeat 1.05** is deliberately mild. Code repeats itself honestly: the same
identifier, the same import, the same closing brace. A penalty tuned for prose
punishes the tokens correct code is made of.

These are a starting point with reasons, not a tuned result.

## Two design decisions worth stating

**A model switched off is not a model, and does not stop the search.** Switching
one off is how somebody says "not this one"; reading it as "nothing above this
either" would let one disabled row cut a subtree off from its parent's choice.

**The default is a column with a partial unique index**, not a settings row
holding an id. This way the default cannot outlive the row it names — a setting
pointing at a deleted model is a deployment that looks configured and cannot
open a session. The index is what makes "the one" true: without it, two rows can
both claim it and the answer becomes a question about row order.

## Verified against a real database — 7/7

| Case | Result |
| --- | --- |
| no organisation → the default | ✓, and `organizationId: null` |
| `a > b > c`, only b configured, project under c | **b**, not a and not the default |
| a child with its own model | beats its parent's — otherwise a parent's choice is a ceiling, not a default |
| a chain configuring nothing | the default |
| a model switched off | skipped, search continues to the parent |
| a second model claiming default | **refused by the index** |
| nothing registered at all | `null` — said at the point of asking, not as an HTTP error on the first model call |

## Verified through real sessions — 9/9

Sessions opened through the vibeagent client, then the `vibe_session.inference`
row read back:

```
no organisation      → qwen3.8-27b-mlx   (org null)
project under c      → org-choice-…      (org b)
empty organisation   → qwen3.8-27b-mlx   (org null)
```

The registered sampling travelled with the choice — `temp 0.5 topK 40 repeat 1.1`
for the organisation's model, which is not the default's. Without that check,
registering parameters would be decoration.

The resolution is written **in the same statement as the prompt and under the
same once-only guard**. A session whose model changed halfway would have a
transcript half of which was written by something else, and every cached prefix
would be wrong.

`organizationId` is recorded beside it because "why is this session on that
model" is the question that follows every surprise, and the answer is one level
of an org chart that the model name does not show.

## Three things this found on the way

**The runtime was pointing at a model that no longer exists.** The worker read
`VIBE_INFERENCE_MODEL`, and that value was the previous endpoint's model, which
had been unloaded. Every session would have failed at its first model call.
The environment is now the fallback, not the answer.

**Two of five registered parameters were being discarded.** `top_k`, `min_p` and
`repeat_penalty` were collected by the admin screen and never put in the request
body. A screen that takes a value and drops it is worse than one that does not
offer it: somebody sets top_k, sees nothing change, and concludes the model
ignores it. All three are sent now, and omitted entirely when unset — an
endpoint that does not know a parameter answers 400 rather than ignoring it.

**A turn could end with nothing and call itself finished.** `answered` was
`!toolCalls.length`, so a reply with empty content and no tool call ended the
turn as a success. What a person saw was a request, a pause, and nothing — no
result and no error. A thinking model makes this reachable: it can spend its
budget on reasoning and emit two newlines as the visible half. That is a model
stopping, not a model answering. It now says so. **Retrying was deliberately not
added** — how many times, with what nudge, at whose cost is a policy, and
inventing one here would bury the behaviour under a workaround before anybody
had seen it happen.

## Residual risk

- **The organisation model is chosen by name order** when an organisation has
  several active. `ORDER BY identifier LIMIT 1` is arbitrary; an organisation
  that attaches two models has expressed a preference nothing records.
- **The resolution is not re-run.** A session opened before a model changed keeps
  the old one, which is intended, but nothing tells anybody that the session
  they are looking at predates the change.
- **The admin screen has no default-model control yet.** The column exists and
  the resolver reads it; setting it currently means a SQL statement or a future
  screen.
- One local model, one endpoint. Nothing here has been tried against an endpoint
  requiring an API key, and `header_value` is read as the key on trust.
