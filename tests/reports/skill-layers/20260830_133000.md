## What the run proved

Six skills published by other people, spread over three layers, ended up as one
index inside a session that was actually opened:

```
- **canvas-design**  /skills/account/<uid>/canvas-design
- **docx**           /skills/project/<pid>/docx
- **mcp-builder**    /skills/org/<oid>/mcp-builder
- **pdf**            /skills/project/<pid>/pdf
- **skill-creator**  /skills/org/<oid>/skill-creator
- **webapp-testing** /skills/account/<uid>/webapp-testing
```

`pdf` was uploaded to two layers. It appears once, pointing at the project's
copy, with the account's recorded as shadowed. The stored `context_suffix` is
byte-identical to what the composer produces.

Every path was read from inside `worker-tool`, and a write to one was refused
with `Read-only file system`.

## Three defects the real skills found

**A real skill could not be uploaded at all.** `app.use(express.json({limit:"64kb"}))`
runs before every route, so it consumed the request and answered 413 long before
the bundle route's own 16 MB limit was consulted. The route declared a generous
limit that was unreachable. Every hand-made bundle in the earlier tests was
under 64 kb; the first real skill — 71 kb — was the first thing to find it. The
global parser now steps aside for the upload path.

**The description was being asked for twice.** A real skill states what it is in
`SKILL.md`'s frontmatter, because that file travels with it. The screen was
asking an admin to retype that sentence into a row, which produces two versions
of it — and the row's is the one that goes stale, since it sits next to nothing
that changes when the skill does. Uploading now reads the frontmatter and writes
it to the row. All six descriptions in the index above were typed by nobody in
this run.

Only when the bundle says something: a skill with no frontmatter leaves whatever
a person wrote. Blanking a description would drop the skill out of the session
index entirely, and "I uploaded files and the skill disappeared" is not a
sentence this should be able to produce.

**A test expectation was wrong, not the code.** The run first asserted `docx`
would contain a binary file. All 61 of its files are text — Python, XSD,
markdown. Deciding editability by content rather than by extension is what makes
that the right answer rather than a guess about `.xsd`. The check became "a real
skill of nothing but text opens entirely", and `canvas-design` took over the
binary case: 54 of its 83 files are fonts, listed and not openable, with the 28
`.txt` licences beside them opening normally.

## Two things the run got wrong about itself

Recorded because both cost a cycle and neither was a product defect.

**The project was created through the wrong door.** `POST /api/projects` on
admin makes the record and nothing else — admin has no workspace mount and
cannot make the folder. The route that makes both is vibeagent's
`POST /api/vibe/workspaces`, which asks admin for the record first and creates
the folder only once that answer is yes. Still worth noting that admin's route
can produce a record with no folder behind it.

**The socket connects when a session attaches, not before.** Waiting for
"online" before creating a session waits for something with no reason to happen.
The open command is queued and flushed once the socket reports online, so
clicking straight through is correct.

## Residual risk

- **Nothing has run a skill yet.** The index reaches the session, the files are
  where it says, and the tool container can read them. No agent has yet read a
  `SKILL.md` and executed what it describes.
- **No skill was enforced.** `mode: enforced` is tested in `admin_domain`, but
  every entry in this run was `default`. An organisation binding a skill a
  person cannot switch off has not been exercised end to end.
- **Nested organisations were not tested.** One organisation, one project, one
  account. A sub-organisation overriding its parent is unit-tested only.
- **`canvas-design` at 2.6 MB is sent as base64 inside JSON**, which is 3.5 MB on
  the wire for 2.6 MB of files. It works and is bounded, but a skill near the
  8 MB limit will be near 11 MB of request body.
- Accounts, organisations, projects and bundles from each run accumulate.
