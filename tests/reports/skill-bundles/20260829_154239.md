## Which locators worked

Every step used the declared hooks; no structural or text-matching selector was
needed after the two fixes below. The panel's `data-path` on both the file
buttons and the editor is what makes "which file is open" answerable without
reading the textarea's contents.

## Two defects the run found

**`SKILL.md` was not first.** The listing sorted root files alphabetically, so a
`Makefile` came ahead of it — correct alphabetically, wrong for reading, and the
sort exists to serve the reading. The unit test had missed it because its
fixture had only one root file; it now has three. Fixed by pinning `SKILL.md`
ahead of everything.

**The read-only mount was on the wrong container.** The first edit put
`/skills:ro` on `vibeagent` — which serves the web client and never runs a
skill's files — and left `worker-tool`, which does, with no mount at all. Found
by asking the containers rather than by reading the compose file: worker-tool
answered `No such file or directory` for a file admin had just written. A
compose mistake of this shape passes every unit test there is.

## Notes and residual risk

- The four console errors in `report.json` are the four refusals in checks
  12–15. A refused request is an HTTP 400, and the browser logs one line per
  400. They are the evidence, not a defect.
- **Two layers refuse a hostile zip entry**, and the messages say which acted:
  `invalid relative path` and `absolute path` are yauzl's, raised before this
  code sees the entry; `path escapes the skill` is ours. Both are wanted — the
  second is what still holds if the zip reader is ever replaced.
- **Not covered:** a session actually loading a skill and running something from
  it. The index now carries each bundle's path, and the loader's layer→folder
  mapping is unit-tested against the layout the admin writes, but no end-to-end
  run has yet had an agent read a `SKILL.md` and follow it.
- **Not covered:** concurrent uploads of one bundle. `extractBundle` removes the
  folder before writing, so two uploads racing would interleave. One editor per
  skill makes this unlikely rather than impossible.
- The upload ceiling is 8 MB and is enforced against the zip's *declared* sizes
  before inflating. A zip that lies downward about its sizes would be caught by
  the per-file write rather than by the ceiling; the file-count and depth limits
  bound what that can cost.
