# 마크다운 렌더링

에이전트의 답변은 마크다운이다. 표와 제목과 코드펜스로 답하도록 학습된 모델이니
당연한 일인데, 그걸 이스케이프한 평문으로 보여주면 내용 대신 문장부호를 읽게 된다.

`front/markdown/` 이 그걸 HTML로 바꾼다. 문서 렌더러와 다른 점이 셋이다.

## 1. 글이 아직 쓰이는 중이다

텍스트가 몇 글자씩 도착하고, 도착할 때마다 화면이 통째로 다시 그려진다. 긴 턴이면
천 번이 넘는다.

- **파싱 결과를 내용으로 캐시한다.** 끝난 블록을 매번 다시 파싱하는 건 답이 바뀔 수
  없는 일을 반복하는 것이다. 아직 쓰이는 중인 블록 하나만 캐시를 비껴간다.
- **`live` 인 블록은 다이어그램도 하이라이트도 하지 않는다.** 잘린 펜스는 다이어그램이
  아니다. 그리려다 실패하면 그 실패가 캐시되어 다시는 기회를 얻지 못한다.
- **미완성 상태는 캐시하지 않는다.** 빈 다이어그램 자리를 캐시하면 나중에 다 그려진
  그림이 들어갈 곳을 영영 잃는다.

## 2. 느린 것은 나중에 온다

mermaid와 highlight.js는 첫 등장에 동적 임포트한다. mermaid는 이 클라이언트가
불러올 수 있는 것 중 제일 크고, 대부분의 대화에는 다이어그램이 없다.

둘 다 비동기라 결과가 나올 때쯤이면 물어봤던 DOM은 이미 몇 번이나 버려진 뒤다.
그래서 **결과를 내용 기준으로 캐시해두고 `whenReady()` 로 "보여줄 게 생겼다"고만
알린다.** 호출자가 다시 렌더하면 그때 캐시에서 꺼내 쓴다. 자리(slot)는 그대로 두고
`hydrateMarkdown()` 이 실제 문서에 대고 채운다.

렌더 직후에 `hydrateMarkdown()` 을 부르는 게 중요하다. 이미 캐시된 것은 같은 프레임에
들어가므로, 다시 그려도 조금 전까지 보이던 다이어그램이 깜빡이지 않는다.

## 3. 모델의 글은 신뢰할 수 없다

모델의 텍스트에는 방금 디스크에서 읽은 내용이 그대로 들어있곤 한다. `cat README.md`
는 이 에이전트가 늘 하는 일이고, 마크다운은 원시 HTML을 설계상 통과시킨다. 그러니
누가 심어둔 `<img onerror>` 하나가 운영자의 토큰을 쥔 세션에서 도는 스크립트가 된다.

- **파싱한 다음 소독한다.** 순서가 반대면 안 된다. 원본을 먼저 소독하면 마크다운이
  망가지고, 마크다운이 일부러 통과시키는 원시 HTML은 출력 시점에만 잡을 수 있다.
- **허용 목록이지 차단 목록이 아니다.** 우리가 미처 생각 못 한 것도 함께 죽는다.
- **`data-*` 는 전부 버린다.** 모델이 `data-testid` 를 만들어내면 그 속성으로 요소를
  찾는 브라우저 테스트가 흔들린다. 렌더러 자신의 표식은 `class` 로 옮겼다 —
  DOMPurify는 목록에 넣어도 낯선 속성 이름을 지우기 때문이기도 하다.
- **`foreignObject` 를 금지한다.** SVG 안에 임의의 HTML이 들어오는 구멍이다. 그래서
  mermaid를 `htmlLabels: false` 로 돌려 라벨을 진짜 SVG 텍스트로 그리게 한다.
- **링크는 전부 바깥으로 나간다.** `target="_blank"` 에 `rel="noopener noreferrer
  nofollow"` — 토큰을 쥔 세션으로 `window.opener` 가 돌아가지 못한다.

## 공개 면

```ts
renderMarkdown(source, { live?, whenReady? }): string   // 대입해도 안전한 HTML
hydrateMarkdown(root): void                             // 다이어그램·하이라이트 채우기
```

## 뷰가 지켜야 할 것

- `hydrateMarkdown()` 은 HTML을 넣은 **직후** 같은 프레임에 부른다
- `whenReady` 는 화면을 다시 그리게 한다. 이벤트가 왔을 때와 같은 경로면 된다
- 스트리밍 중인 블록에는 `live: true` 를 준다
- **도구 출력은 마크다운이 아니다.** stdout은 명령이 뱉은 바이트지 문서가 아니므로
  그대로 둔다. `ls` 결과를 마크다운으로 흘려보내면 정렬이 무너진다

## 가로 스크롤

넓어질 수 있는 것 — 표, 코드펜스, 다이어그램 — 은 전부 자기 상자 안에서 스크롤한다.
그리고 말풍선에 `min-width: 0` 이 필요하다. 그리드 아이템의 자동 최소 크기는 내용의
최소 크기라서, 넓은 자식 하나가 말풍선을 열보다 넓게 만들고 대화 전체가 옆으로
스크롤된다. 스트리밍 중에 특히 드러난다. 펜스가 단어 중간에 도착하면 그 순간
그 줄만큼 넓어지기 때문이다.
