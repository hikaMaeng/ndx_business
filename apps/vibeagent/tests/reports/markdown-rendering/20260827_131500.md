## 고친 결함

1. **DOMPurify가 렌더러 자신의 표식을 지웠다.** `ALLOW_DATA_ATTR: false` 는 허용
   목록에 적어둔 `data-mermaid` 까지 포함해 모든 `data-*` 를 지운다. 그래서
   hydrate가 채울 자리를 찾지 못했다 — 다이어그램도 하이라이트도 영영 안 나온다.
   표식을 `class` 로 옮겼다. 낯선 이름의 커스텀 속성도 마찬가지로 지워지기 때문에
   속성에 의존하는 길은 아예 버렸다. 부수 효과로 모델이 `data-testid` 를 만들어낼
   수도 없게 됐다.

2. **`foreignObject` 를 막아 다이어그램이 빈 채로 나왔다.** mermaid는 기본적으로
   노드 라벨을 `foreignObject` 안의 HTML로 그린다. 소독기가 그걸 지우니 빈 상자만
   남고, 914×1854짜리 빈 SVG가 됐다 — 사용자가 본 "거대한 빈 공간과 가로
   스크롤바"의 정체다. 구멍을 열어주는 대신 `htmlLabels: false` 로 라벨을 진짜 SVG
   텍스트로 그리게 했다.

3. **mermaid의 `viewBox` 가 실제로 그린 것보다 작았다.** 라벨을 SVG 텍스트로 바꾸니
   mermaid의 예측과 실제 렌더가 어긋나 노드 오른쪽이 잘렸다 (`viewBox` 는 x=72.7
   까지인데 내용은 x=121까지). 문서에 들어간 뒤 `getBBox()` 로 실측해서 `viewBox` 를
   다시 씌운다. 그릴 때는 그 SVG가 어느 문서에도 속하지 않아 잴 수가 없다.

4. **말풍선이 대화 열보다 넓어졌다.** 위의 가로 스크롤 항목. `min-width: 0` 을 줬다.

## 남은 위험

- **스트리밍 중 샘플링을 도구 호출 사이에 이어갈 수 없다.** 브라우저 도구의 각
  호출이 격리된 컨텍스트라 `window` 에 남긴 표본이 다음 호출에서 안 보인다. 그래서
  스트리밍 중 넘침은 연속 관측 대신 **최악 형태 주입**으로 증명했다. 잘린 펜스가
  만드는 모양(아주 긴 `pre`)을 직접 넣어 검사한 것이라 대표성은 있지만, 실시간
  관측 자체는 아니다.
- **구식 세션은 여전히 비어 보인다.** 다른 작업 줄기가 넣고 있는 뷰 프로젝션
  (`vibe_turn_view`, `vibe_block_view`) 은 새 턴부터 채워진다. 그 전에 만들어진
  세션은 행이 없어 기록이 안 나온다. 마크다운과는 무관하고, 백필이 필요하다.
- **도구 출력은 일부러 마크다운으로 그리지 않는다.** stdout은 문서가 아니다.
  사용자가 스크린샷에서 읽기 어려워한 `cat README.md` 출력은 여전히 평문인데,
  그건 명령이 뱉은 바이트를 그대로 보여주는 게 맞기 때문이다.
