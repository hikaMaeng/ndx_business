# Test Report: multi-client load performance

## Timestamp

2026-08-20 14:47 (local)

## Changes

- `481e6b8`: parallel durable ingress handoff lanes.
- `f5a1e51`: load harness distributes requests across independent streams.
- `08d41ff`: PGMQ long-poll, queue write, and durable transaction pools are isolated.
- `72472ec`: default worker capacity is detected CPU count × 2 (96 on this host).

## Workload

- 2,048 requests, four channels, 512 independent session streams.
- 96 prewarmed workers; each `test.delay` worker action waits 5 seconds then emits a result event.
- Dedicated `agent_load_requests` and `agent_load_results` queues; the shared queues were not used.

## Finding and fix

The first 96-worker run exposed pool starvation: 32 `pgmq.read_with_poll` calls occupied the
single 16-connection database pool (`PgSleep`), preventing durable scheduler commits. The run was
stopped, and only its identified dedicated test jobs/results were removed. `08d41ff` assigns
separate pools to PGMQ readers, queue writers, and durable state. The repeated workload produced
the result above.
