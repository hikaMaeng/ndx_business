## Failures

### 이번 작업에서 발견하고 고친 것

1. **브라우저가 admin에 직접 로그인 시도** — 최초 구현은 클라이언트가 `http://admin:18080`으로 fetch했다. 이는 compose 내부 호스트명이라 브라우저가 해석하지 못해 로그인이 조용히 실패했다(토큰 미저장, 오류 표시도 없음). 게이트웨이가 admin으로 프록시하도록 고치고 오류 처리를 추가했다.
2. **worker 번들 1.4MB** — `worker-entry.ts`가 broker barrel을 import해 `pg`·`express`·`ws`를 워커 스레드 번들에 끌어왔다. `agent/broker/worker` subpath로 분리해 14.2kb로 줄였다.
3. **턴 제출이 HTTP였음** — 최초 구현은 `POST /api/vibe/turns`였다. 그러면 소켓이 알림 채널로 격하되고 하나의 대화가 두 전송으로 쪼개진다. 제출을 소켓 이벤트로 옮기고 HTTP 라우트를 제거했다.

### 남은 것

1. **`admin_domain` 단위 테스트 1건 실패** — `organization snapshot parser validates appearance tokens`. 이번 작업에서 `packages/admin_domain`을 전혀 수정하지 않았고(순수 파서 로직) **기존 `master`의 결함**이다. 범위 밖이라 고치지 않았다.
2. **구조 검사 warn 2건** (violation 아님)
   - `wire-in-app-boundary` — `VibeSnapshot`(화면 뷰 모델, 오탐), `ChatMessage`(외부 OpenAI 계약이라 우리 `common/protocol`에 둘 대상이 아님)
   - `wire-outside-protocol` — broker의 기존 5개 타입. 라이브러리화 이전과 동일하며 검사 범위에 들어오며 드러난 기존 부채
3. **자동화 도구의 좌표 클릭이 먹지 않음** — Browser 창이 표시되지 않으면 페이지가 프레임을 합성하지 않아 `left_click(coordinate)`가 반영되지 않는다. 계산기 최초 검증에서 표시값이 `0`으로 남아 페이지 결함처럼 보였으나, JS로 실제 버튼 `.click()`을 호출하니 정상 동작했다. **도구 제약이지 산출물 결함이 아니다.**

이번 클라이언트는 `data-testid`와 `aria-label`을 처음부터 넣어 만들었고, 이전 화면에서 문제가 됐던 번역 문자열 의존이 사라졌다. `find` 도구도 별도 실패 없이 `read_page` → ref 경로로 해결됐다.

플레이키 위험 두 가지. 첫째, 생성된 페이지에는 test id가 없어 표시 텍스트에 의존한다 — 에이전트가 만든 마크업이라 통제할 수 없고, 매 실행마다 달라질 수 있다. 둘째, 턴 완료 대기를 폴링으로 하므로 모델이 느린 날에는 대기 상한을 늘려야 한다.
