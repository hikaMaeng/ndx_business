# 펜싱 토큰 — 실행 보고

- 계기: 앞선 보고의 "남은 창" — 리스 만료와 원래 워커의 인지 사이에 두 실행이 겹침
- 실행: 2026-08-27 15:30 ~ 16:10 (KST)
- 결과: **닫았다.** 되돌릴 수 없는 효과 하나(bash spawn)에 대해

## 무엇이 열려 있었나

`agent_execution` 의 리스가 만료되면 다른 워커가 재클레임한다. 원래 워커는 다음
heartbeat(현재 visibility/3 = 20초)에서야 그걸 알고 abort한다. 그 사이 두 attempt가
모두 자기가 주인이라고 믿는다.

정체성을 가진 기록은 이 창에서도 안전하다 — 논리키와 자연키로 전부 접힌다.
안전하지 않은 것은 **기록이 아닌 것** 하나뿐이었다: bash 실행.

## 넣은 것

### 계약

`WorkerExecute` 의 네 번째 인자를 컨텍스트 객체로 정리했다. 위치 인자를 다섯 개로
늘리는 것보다 낫고, `queue` 와 `fence` 가 같은 성격("이 실행에 대해 워커가 알아야
할 것")이라 함께 있는 편이 맞다.

```ts
interface WorkerContext {
  queue: string;
  fence(): Promise<boolean>;
}
```

`fence()` 는 리스를 **갱신하면서** 소유 여부를 답한다. 묻는 행위가 곧 앞으로 필요한
새 리스를 사는 것이기도 하다. DB에 닿지 못하면 `false` 다 — 증명되지 않은 소유는
소유가 아니다.

### 두 풀 모두에서 진짜로 동작한다

인라인 실행에서는 함수 호출이다. 스레드 풀에서는 리스가 부모에 있으므로
postMessage 왕복으로 구현했다 — `{type:'fence'}` 를 보내고 `{type:'fence-result'}`
로 답을 받으며, 질문마다 번호를 붙여 답을 짝지운다.

"스레드에서는 지원 안 함" 으로 두지 않은 이유는, 그렇게 두면 지원되지 않는 경로가
`true` 를 돌려주는 거짓말이 되기 때문이다.

### 거는 자리

`runTool` 의 spawn 직전. 마지막 관문이다.

```ts
if (!await fence()) throw new Error(`refusing to run ${toolCallKey}: the execution lease has moved to another worker`);
```

**던진다, 조용히 넘어가지 않는다.** 그 메세지가 처리된 것으로 취급되면 안 되기
때문이다 — 지금 소유한 워커가 처리할 것이다.

인퍼런스 호출에는 걸지 않았다. 비싸지만 되돌릴 수 없는 것은 아니고, 답변은
논리키로 접히므로 두 번 불러도 히스토리는 하나다. 되돌릴 수 없는 것에만 건다.

## 검증

단위 테스트 2개 추가(총 44개). 순서까지 확인했다.

```
order: ["checked-history", "fenced"]   ← 펜스가 프로세스 시작 직전 마지막 관문
```

**펜스를 제거하면 실제로 실패하는지 확인했다.**

```
✖ an attempt that no longer owns the execution refuses to run the command
✖ ownership is confirmed before spawning, not after
```

복원 후 44/44 통과.

**정상 작업을 막지 않는지가 더 중요하다.** 펜스는 아무것도 거부하지 않을 때가
정상이다. 병렬 도구 호출 턴을 새로 돌렸다.

```
tool.requested  progress 4
tool.started    progress 4      ← 넷 다 실제로 시작됨
tool.completed  progress 4
iteration.ready progress 2
turn.final      progress 1
파일: f1.txt f2.txt f3.txt 생성
워커 로그의 "lease has moved" 건수: 0
```

건강한 실행은 하나도 막히지 않았다.
