## 1단계 — 서버 역할 폴더 분리

게이트웨이(소켓·브로커)와 워커가 한 파일에서 `if`로 갈렸다. 셋은 의존성도 실패
양상도 변경 이유도 다르다.

```
server/{gateway/{routes,verifier},worker,dispatcher,reactions}/ + index.ts(32줄)
```

import를 동적으로 바꿔서 워커가 게이트웨이의 풀과 라우트 표를 더 이상 만들지 않는다.

**실기능 테스트**: 분리된 게이트웨이로 턴 종단 실행 — 2이터레이션, 1도구,
`stoppedBy: final`, 파일 생성.

## 2단계 — 프론트를 리액트 + 모델렌더로

리액트를 쓰기로 한 근거: 저장소의 선언된 스택이고, `admin`이 이미 같은
`Emitter`/`SliceModel`/`useSyncExternalStore`를 돌리고 있으며, "바뀐 것만 다시
그리기"의 어려운 부분인 증분 DOM을 리액트가 이미 맞게 한다.

- 프리미티브는 `admin_domain`에서 **바이트 단위로 복사** (스킬: 재생성 금지)
- 슬라이스: `identity` / `workspace` / `sessionError` / `turns` / 턴별 `TurnModel`
- 불변 spread 19곳 제거 → in-place mutate + emit
- 소유권: 컴포저가 초안을, 프로젝트 행이 펼침 여부를, 폼이 입력을 각각 소유.
  루트는 레이아웃과 "로그인했는가"만
- `main.ts` 563줄 → 루트 79줄 + 기능 폴더

### 수용 기준 — 실측

스트리밍 턴 하나 동안:

```
sidebarSameElement  true      (같은 DOM 객체)
rowsSurvived        50 / 50   (세션 행 전부 identity 유지)
totalMutations      935
sidebarMutations    0         ← 핵심
```

반대편에서도 단위 테스트로 못 박았다: 델타 20건이 자기 턴을 20번 깨우고,
형제 턴과 턴 목록은 **0번**.

### 잡은 결함 2건

1. **조건부 훅.** `useModel(a).value !== "" && useModel(b).value !== ""` 는 첫
   조건이 거짓이면 두 번째 구독을 건너뛴다. 화면이 백지가 됐고 콘솔이
   React #310으로 즉시 지목했다. 브라우저에서 돌리지 않았으면 못 봤다.
2. **`VibeSnapshot`** 은 뷰 상태인데 wire 타입의 이름을 달고 있었다. 체커가
   프로토콜 위반으로 읽던 원인이고, 이제 모델이 뷰이므로 개명이 아니라 삭제했다.

### 실기능 테스트

새 클라이언트로 프로젝트 개설 → 세션 개설 → **계산기 2턴 제작** → 눌러서 검증.

```
7*8=56  9+6=15  12/4=3  5-8=-3  1.5+2.5=4  3..1→3.1  C→0
```

1턴 산출물에는 **자바스크립트가 아예 없었다**(마크업만). 2턴으로 고치게 했고,
그 왕복이 멀티턴·접기 경로도 함께 검증했다 — 접힘 9블록 → 펼침 15블록(실제
명령, 하이라이팅 606개) → 다시 접힘 9블록, 답변 유지.

## 3단계 — wire 타입

이름 규칙 경고를 그대로 따르지 않고 규칙의 **목적**으로 판단했다: 양쪽이 합의해야
하는 형태가 한쪽에만 있으면 어긋난다.

| 처리 | 대상 |
| --- | --- |
| protocol로 이동 | `ResultPayload`(이벤트에 저장되어 소켓으로 나감), `MetricsSnapshot`(HTTP로 서빙) |
| 삭제 | `StreamEvent = EventEnvelope` — 이름만 바꾸는 별칭 |
| 두고 근거 기록 | `AuthedRequest`, `EventQueueMessage`, `DatabasePoolSnapshot`, `PendingMessage`, `ChatMessage` |

`ChatMessage`는 **제3자** 추론 API로 나가는 형태다. 규칙이 말하는 "양쪽"이 이
저장소에 없고, `common`에 두면 브라우저가 알 이유 없는 형태를 보게 된다.

경고 추이: wire-outside-protocol **6 → 3**, wire-in-app-boundary **3 → 2**.
남은 것은 전부 이름 오탐이며 판단 근거를 `packages/agent/docs/constraints.md`에 남겼다.

**실기능 테스트**: README.md 작성 후 렌더 검증. 에이전트가 `cat`으로 찍은 표는
도구 출력 안에 평문으로(파이프 4개), 마크다운 영역에는 **0개** — 명령이 뱉은
바이트를 마크다운으로 흘리지 않는다는 규칙이 지켜졌다. 답변 자체는 리스트 4·코드
6·강조 4로 실제 렌더된다.
