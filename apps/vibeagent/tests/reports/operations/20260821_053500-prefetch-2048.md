## Acceptance model

`ceil(2048 / 96) × 5,000 = 110,000 ms` is the worker-only lower bound. The test allows 15,000 ms for ingress, durable append, attempt reservation, result/outbox commit, and PGMQ publication: maximum 125,000 ms.

The scheduler keeps at most `AGENT_MAX_THREADS + AGENT_MAX_QUEUE` durable attempts active. The extra 64 attempts are waiting only in the bounded WorkerPool queue, so a worker can receive the next task without waiting for the previous task's terminal database commit. Worker execution remains fixed at 96 threads.
