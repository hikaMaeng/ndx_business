## 5. 실제 조작 — 세 번 만에 통과

**턴 1 산출물은 동작하지 않았다.** 모든 버튼이 `0`을 반환했고, 원인은 산출물 자체의
결함 세 개였다.

1. `updateDisplay()`가 `display.value`에 대입하는데 `#display`는 `<div>`다 — `.value`가
   없어 화면이 갱신되지 않는다
2. 연산자 id가 `btn-plus`인데 핸들러가 `/[+\-*/]/.test("plus")`로 판정한다 — 참이 될 수 없다
3. (턴 2 이후 드러남) 리스너를 `querySelectorAll('#grid button')`으로 붙이는데 컨테이너는
   `<div class="grid">`다 — 매칭 0건이라 **어떤 리스너도 붙지 않았다**

1·2는 턴 2에서, 3은 턴 3에서 고쳐졌다. 세 번째 결함은 앞의 둘을 고친 뒤에야 드러났다.
매 턴마다 브라우저 캐시를 우회해(`?cachebust=`) 서빙본이 최신인지 먼저 확인한 뒤 조작했다.

턴 3 이후 실제 클릭 결과:

## 6. 구조 재생성 없음

세 턴이 끝난 뒤 다시 확인했다.

```
queues              : agent_requests
tables              : agent_execution, agent_execution_recipient,
                      event_store, event_stream_sequence, event_subscription_cursor
agent_requests backlog : 0
이 세션 채널 이벤트     : 134
```

134건 전부가 로그 tail만으로 브라우저에 전달됐고, 구 큐·테이블은 다시 생기지 않았다.

## 실패

없음. 5절의 세 결함은 에이전트 **산출물**의 결함이며 전달 경로와 무관하다.

## 재현성

계획의 단계를 순서대로 따르면 재현된다. 단, 5절은 모델 출력에 달려 있어 결함의
개수와 종류는 실행마다 달라진다. 재현해야 하는 것은 "동작할 때까지 같은 세션에서
턴을 이어 붙일 수 있다"는 성질이지 결함 목록이 아니다.

## 로케이터 관찰

계획의 `data-testid` 계약으로 전부 처리됐고 모호함은 없었다. 두 가지를 기록한다.

- 브라우저 창이 표시되지 않은 상태에서는 `computer` 도구의 클릭과 스크린샷이
  동작하지 않는다(프레임 합성이 멈춘다). 조작은 JS `.click()`으로 대신했다.
  제품 결함이 아니라 도구 제약이다.
- `/workspace` 정적 서빙은 캐시된 사본을 준다. 산출물을 다시 볼 때는 쿼리 문자열로
  캐시를 깨야 하며, 그러지 않으면 고친 파일을 두고 옛 동작을 보게 된다.

## 남은 위험

- 브로커 다중화는 이 실행에서 실증하지 않았다. tail이 서로를 막지 않는다는 것은
  단위 테스트(`log-tail.test.ts`의 독립 tail 2개)로만 확인했다. `gateway-ha` 프로파일로
  Gateway 두 대를 띄운 실측이 남아 있다.
- 로그 보존 정책을 아직 정하지 않았다. 큐의 `delete`가 하던 청소를 이제 아무도 하지
  않으므로 `AGENT_RETENTION_DAYS`가 유일한 상한이다.
- `head 위치 − 커서` 지표를 아직 내보내지 않는다. tail이 뒤처지는 것을 관측할 수단이
  `logTailReads`/`logTailEvents` 계수기뿐이다.
- 부하 하네스(`tests/load/*.mjs`)는 아직 구 스키마(outbox·gateway ledger)를 참조하므로
  현재 실행되지 않는다.
