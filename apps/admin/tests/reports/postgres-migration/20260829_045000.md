# Admin onto PostgreSQL — execution report

- **When**: 2026-08-29 04:50 KST
- **Verdict**: **PASS.** Admin runs entirely on PostgreSQL, the 28 accounts are
  byte-identical to what they were, and two defects found on the way are fixed.

## What was actually outstanding

The DDL for this had been written on 2026-08-13 (`2d41f81`, "stage postgres
schema migration") as a standalone script and never wired in. Admin kept running
on the old store; `DATABASE_URL` sat in its environment with nothing reading it.
A later merge (`5a9df4b`) dropped even that script.

Translating the schema was never the work. `node:sqlite` is synchronous and
`pg` is not, so **44 domain functions and 29 route handlers had to become
async** — that is the part that had not been started.

## Two defects in the recovered DDL and the old opener

| Found | Consequence if shipped |
| --- | --- |
| `email TEXT COLLATE NOCASE UNIQUE` had been translated to plain `text UNIQUE` | `A@x.com` and `a@x.com` become two accounts for one person. Now `citext`. |
| the old opener seeded `auth_settings` row 1; the new schema did not | Every settings write is `UPDATE … WHERE id = 1`, which on an empty table changes nothing **and reports success**. Seeded in `ensureAdminSchema`. |

The second is verified below rather than argued: settings were changed, re-read,
and restored.

## Data

28 accounts, dumped from both stores as `id|email|password_hash|status|created_at`
and diffed: **identical**, hashes and timestamps included. Login returns 200 with
a password set before the move, which is the same fact stated by the system
itself.

## Browser verification — Admin

Signed in on PostgreSQL, one `/api/auth/login` and one `/api/auth/me`, no loop.
Then, with a temporary master grant, every write path:

| Path | Result |
| --- | --- |
| create root organisation | 201 |
| create child under it | 201 |
| assign member, assign `subtree` responsibility | 200, 200 |
| remove member (two-statement transaction) | 200 |
| rename + recolour | 200, visible on re-read |

| settings write | 3600 → 7200 → read back 7200 → restored |
| model catalog, project defaults, projects | 200, 200, 200 |

The grant was reverted and the revocation confirmed: 403 on `/api/models` and
`/api/admin/settings`, `isMasterAdmin: false`.

## Browser verification — the coding agent

Projects are now created under the account that owns them, as git repositories:

```
workspace/<userId>/<project>/.git
workspace/<userId>/<project>/.gitignore
```

- branch `main`, one commit, author **the account that created it**, tree clean
- the record lands in Admin with the owner joined
- a second name from the same account is refused; the same name from a
  **different** account creates a separate folder under that account
- the second account's project list is empty — isolation by path composition,
  not by a filter
- a full agent turn ran end to end (3 iterations, 2 tool calls, `stoppedBy: final`)
  and its file landed under the account folder

## The defect that only a restart could show

Redeploying Admin restarts the database every service shares. `pg` raises an
`error` event on a pool when an **idle** client is dropped, Node treats an
unhandled `error` event as fatal, and the broker died and came back up serving
`{"status":"standby"}` — healthy by its own health check, useless to a browser.

Both pool factories now handle it. Reproduced deliberately after the fix:
`docker compose restart admin`, and the broker's start time was unchanged, the
app still served, and the drop appears as
`{"event":"database.pool.idle.dropped","error":"terminating connection due to administrator command"}`.

## Two smaller things

- The session's stored workspace is `<userId>/<project>` because everything
  downstream resolves from the projects root. The screen showed that verbatim —
  an account id where a project name belongs. Both the header and the sidebar
  now use one shared `workspaceDisplayName`, and no UUID appears on screen.
- WebSocket errors seen in the console were the client retrying across a
  redeploy. Checked rather than assumed: a socket opened on the first try
  afterwards.

## Residual risk

- **48 project folders sit at the projects root with no owner.** They predate
  ownership, so nothing can attribute them. They are invisible to the picker
  now. Nothing was deleted.
- **The artefact server answers 200 for paths that do not exist**, returning the
  client app. A broken artefact link therefore looks like a working one. This is
  older than these changes but the account folders make wrong paths likelier.
- **The old store's file is still on disk** (141 MB plus a 140 MB WAL). Nothing
  reads it. Left in place deliberately.
- Test suites now need a real PostgreSQL. They skip with a stated reason rather
  than fail when `TEST_DATABASE_URL` is unreachable, which is honest but means a
  green run on a machine with no stack proves less than it used to.
