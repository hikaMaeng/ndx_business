# Constraints

Queue delivery is at-least-once beyond its visibility timeout. `EventQueueTransport` is the only consumer-facing delivery contract; PGMQ-specific SQL stays in `src/server/pgmq`. The durable-state Postgres pool is injected separately and owns execution claims, results, and event history. The transaction key makes retries safe only when the action's external side effects also use the same idempotency boundary. Unknown actions fail into a result event and are not executed dynamically.

The contract targets visibility-aware queue systems such as PGMQ, SQS, Redis Streams, and NATS JetStream. Kafka is outside the drop-in contract because offset commits do not provide message-level delete and visibility semantics.

`event_store` is the only append target for canonical events; `agent_events` is frozen legacy data and is no longer written. `sequence` is a PostgreSQL `bigint` carried in the envelope as an exact decimal string: cursor comparison must use bigint-aware storage comparison, never JavaScript number coercion. Schema initialization raises every `event_stream_sequence` counter to its stream's stored maximum. Each transaction durably registers one recipient per `replyChannel`; terminal success, worker failure, and permanent processing failure fan out to every registered channel. Their deterministic IDs include that channel, so duplicate submissions to one channel converge while different channels each receive one observable terminal event. Conflict remains request-scoped. `EventStore.appendMany()` commits every terminal envelope, its `event_outbox` reservation, and the fenced `agent_execution` completion in one PostgreSQL transaction; only fenced outbox attempts call PGMQ/WebSocket after commit. Send failure returns the outbox row to `ready` without rewriting immutable event or execution state. Every derived event stays in its cause's stream, so per-stream ordering and session projections cover results as well as commands.

`session_view`, `run_view`, `turn_view`, and `tool_view` are disposable CQRS projections. Each owns an independent `{streamId: sequence}` checkpoint in `event_projection_checkpoint`; a failed projection cannot move another projection's checkpoint, and any one view can be truncated then reconstructed from `event_store`.

Outbox publication is at-least-once. `AGENT_OUTBOX_RETRY_BASE_MS` uses capped exponential backoff and `AGENT_OUTBOX_MAX_ATTEMPTS` moves a terminally undeliverable row into `event_outbox_dlq`; the canonical event remains replayable and is never deleted by this transition. Worker process error or exit is retryable, unlike a handler-reported timeout/cancellation/failure result. Before a durable job retry, the scheduler fences and backdates its owned execution lease so the next matching claim reclaims it rather than joining a stranded running transaction.

`GET /metrics` is disabled unless `AGENT_METRICS_TOKEN` is set and must stay aggregate-only, because the Agent host port is published in the default Compose profile.

`GET /ready` requires both the queue adapter and the durable PostgreSQL pool. `/metrics` includes total, idle, and waiting connections for the durable, ingress-reader, and queue-writer pools; a growing `*PoolWaiting` value is a saturation signal, not a worker-utilization signal. On SIGTERM/SIGINT the service closes listeners, stops ingress, lets currently claimed work drain for at most `AGENT_SHUTDOWN_GRACE_MS`, then terminates workers before closing pools. A drain timeout is structured-log visible; durable leases make interrupted work reclaimable after restart.

`processingRetries`, `processingJoined`, and `processingDlqTotal` are monotonic operator counters; `processingDlq` is the current failed-job gauge. An active transaction collision joins the durable owner and increments only `processingJoined`; it must not consume the retry/DLQ budget or execute again. Alert on a sustained retry/DLQ increase together with nonzero ready age, rather than on individual payloads. `agent_execution_recipient` stores only routing and causation metadata, never the original command payload, and shares the lifetime of the corresponding durable idempotency claim; the current product contract retains idempotency claims indefinitely, so there is intentionally no independent recipient prune. A future finite idempotency window must prune both atomically.

Completed/failed processing jobs, finished processing attempts, and published outbox rows are operational ledgers, not immutable event history. `ProcessingStore.pruneOperationalLedgers()` removes them after `AGENT_OPERATIONAL_RETENTION_DAYS` (30 by default), at startup and every 24 hours; it never deletes `event_store`, active attempt/lease rows, live outbox leases, or `agent_execution` idempotency claims.

WebSocket egress accepts only `protocol/channel` frames. A cursor is an opaque UUID backed by PostgreSQL state, channel-fingerprint-bound, and holds exact decimal stream positions without putting a multi-stream vector in the client token. Its position advances only after the socket reports a successful send, so a disconnect can replay a duplicate but cannot skip an unsent event. `AGENT_CURSOR_RETENTION_DAYS` prunes abandoned cursors. Each connection owns an `AGENT_WEBSOCKET_MAILBOX_MAX` bounded queue and an `AGENT_WEBSOCKET_BUFFERED_BYTES` socket-buffer ceiling; `/metrics.websocketMailboxQueued` is the aggregate queued-event lag and returns to zero when a connection is disposed. Progress/control events may be dropped under pressure, but a full queue or socket buffer closes only that slow connection for durable terminal traffic; it never delays another channel subscriber. Channel routing uses a reverse index, never a scan of unrelated subscribers. Replay reads at most `AGENT_WEBSOCKET_REPLAY_MAX` rows per page; `subscribed.replayComplete=false` is followed by an idle `replay` frame, and the client must resubscribe with that cursor before it can receive live events. The high-water/live handoff buffer has the mailbox bound and closes the one connection rather than retaining unbounded terminal traffic. The browser persists `{ channels, cursor }`, accepts it only for the current normalized channel fingerprint, and removes legacy, malformed, or mismatched entries before opening a socket. It reconnects with a 500 ms to 5,000 ms capped exponential backoff; a channel-set change discards that cursor before reconnecting.
