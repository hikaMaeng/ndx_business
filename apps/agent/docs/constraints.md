# Constraints

Queue delivery is at-least-once beyond its visibility timeout. `EventQueueTransport` is the only consumer-facing delivery contract; PGMQ-specific SQL stays in `src/server/pgmq`. The durable-state Postgres pool is injected separately and owns execution claims, results, and event history. The transaction key makes retries safe only when the action's external side effects also use the same idempotency boundary. Unknown actions fail into a result event and are not executed dynamically.

The contract targets visibility-aware queue systems such as PGMQ, SQS, Redis Streams, and NATS JetStream. Kafka is outside the drop-in contract because offset commits do not provide message-level delete and visibility semantics.

`event_store` is the only append target for canonical events; `agent_events` is frozen legacy data and is no longer written. `sequence` is a PostgreSQL `bigint` carried in the envelope as an exact decimal string: cursor comparison must use bigint-aware storage comparison, never JavaScript number coercion. Schema initialization raises every `event_stream_sequence` counter to its stream's stored maximum. Each transaction durably registers one recipient per `replyChannel`; terminal success, worker failure, and permanent processing failure fan out to every registered channel. Their deterministic IDs include that channel, so duplicate submissions to one channel converge while different channels each receive one observable terminal event. Conflict remains request-scoped. A terminal envelope and its `event_outbox` reservation commit in the same `EventStore.append()` transaction; only fenced outbox attempts call PGMQ/WebSocket after commit. Send failure returns the outbox row to `ready` without rewriting immutable event or execution state. Every derived event stays in its cause's stream, so per-stream ordering and session projections cover results as well as commands.

`session_view`, `run_view`, `turn_view`, and `tool_view` are disposable CQRS projections. Each owns an independent `{streamId: sequence}` checkpoint in `event_projection_checkpoint`; a failed projection cannot move another projection's checkpoint, and any one view can be truncated then reconstructed from `event_store`.

`GET /metrics` is disabled unless `AGENT_METRICS_TOKEN` is set and must stay aggregate-only, because the Agent host port is published in the default Compose profile.

`processingRetries`, `processingJoined`, and `processingDlqTotal` are monotonic operator counters; `processingDlq` is the current failed-job gauge. An active transaction collision joins the durable owner and increments only `processingJoined`; it must not consume the retry/DLQ budget or execute again. Alert on a sustained retry/DLQ increase together with nonzero ready age, rather than on individual payloads. `agent_execution_recipient` stores only routing and causation metadata, never the original command payload, and shares the lifetime of the corresponding durable idempotency claim; the current product contract retains idempotency claims indefinitely, so there is intentionally no independent recipient prune. A future finite idempotency window must prune both atomically.

Completed/failed processing jobs and published outbox rows are operational ledgers, not immutable event history. `ProcessingStore.pruneOperationalLedgers()` removes them after `AGENT_OPERATIONAL_RETENTION_DAYS` (30 by default), at startup and every 24 hours; it never deletes `event_store`, live outbox leases, or `agent_execution` idempotency claims.

WebSocket egress accepts only `protocol/channel` frames. A cursor is an opaque UUID backed by PostgreSQL state, channel-fingerprint-bound, and holds exact decimal stream positions without putting a multi-stream vector in the client token. Its position advances only after the socket reports a successful send, so a disconnect can replay a duplicate but cannot skip an unsent event. `AGENT_CURSOR_RETENTION_DAYS` prunes abandoned cursors. Each connection owns an `AGENT_WEBSOCKET_MAILBOX_MAX` bounded queue and an `AGENT_WEBSOCKET_BUFFERED_BYTES` socket-buffer ceiling. Progress/control events may be dropped under pressure, but a full queue or socket buffer closes only that slow connection for durable terminal traffic; it never delays another channel subscriber.
