# Internals

`src/server/queue/transport.ts` owns the broker-neutral delivery contract. `src/server/pgmq` owns PGMQ SQL calls and implements that contract. `src/server/database.ts` constructs the separately injected Postgres pool.

`src/server/event-store` owns immutable canonical envelopes: it serializes equal event IDs with a transaction advisory lock, returns an existing row without reserving another sequence, and assigns a per-stream sequence only to a new row. `sequence` is a `bigint` exported as an exact decimal string, never a lossy JavaScript number. `ensureSchema` backfills `session_id`, `run_id`, and `turn_id` using legacy payload keys and the `session:` stream prefix, then raises every stream counter to the stored maximum.

`src/server/ingress` converts the deployed queue contract into that canonical draft. A result carries no session payload, so `toResultDraft` derives it from the persisted request envelope: stream, session, run, turn, and correlation are inherited and `causationEventId` points at the request. Results therefore stay in the requesting session's stream instead of collecting in one global channel stream.

The consumer awaits the append before any PGMQ delete. Result identity is derived — `result:<transactionKey>` and `conflict:<eventId>` hashed into a stable UUID. `src/server/delivery` claims each result with a durable lease of `AGENT_DELIVERY_LEASE_SECONDS` and marks it delivered only after queue and hub publication. The claim is three-valued: `delivered` lets a source redelivery be acknowledged without sending again, `leased` means another attempt is still running and raises rather than acknowledging, and only `claimed` sends. Acknowledging a `leased` result would drop it, because the holder may still fail. Worker completion is recorded before this egress attempt, and egress errors never rewrite that terminal execution state. Only `runToOutcome` classifies failure, so a durable-state or egress error is never delivered to the client as `worker_failed`; it raises, the message stays unacknowledged, and the batch continues with the next message. The visibility timer is released in a `finally` that covers every exit path — a leaked timer would extend the message forever and strand the event, neither acknowledged nor redelivered. `src/server/consumer.ts` owns the single async read/process loop, bounded reconnect backoff, CPS-style result transition, and periodic message-visibility extension while one message runs. `src/server/execution` stores the transaction-key claim. `src/server/metrics` holds the aggregate counters behind `GET /metrics`. `src/server/worker` owns a lazy bounded Worker Thread pool and the worker action allow-list; no worker is created for an empty queue.

`agent_events` is frozen. The consumer no longer writes it, `event_store` is the only append target, and the table is kept read-only for rows written before the canonical store existed. Phase 7 of the [Agent Renewal plan](../../../agentRenewal.md) drops it.
