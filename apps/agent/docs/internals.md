# Internals

`src/server/queue/transport.ts` owns the broker-neutral delivery contract. `src/server/pgmq` owns PGMQ SQL calls and implements that contract. `src/server/database.ts` constructs the separately injected Postgres pool.

`src/server/event-store` owns immutable canonical envelopes: it serializes equal event IDs with a transaction advisory lock, returns an existing row without reserving another sequence, and assigns a per-stream sequence only to a new row. `sequence` is a `bigint` exported as an exact decimal string, never a lossy JavaScript number. `ensureSchema` backfills `session_id`, `run_id`, and `turn_id` using legacy payload keys and the `session:` stream prefix, then raises every stream counter to the stored maximum.

`src/server/ingress` converts the deployed queue contract into that canonical draft. A result carries no session payload, so `toResultDraft` derives it from the persisted request envelope: stream, session, run, turn, and correlation are inherited and `causationEventId` points at the request. Results therefore stay in the requesting session's stream instead of collecting in one global channel stream.

`startIngressConsumer` starts `AGENT_INGRESS_CONSUMERS` independent durable-handoff lanes. Each awaits canonical append and `event_processing_job` insertion before PGMQ delete, then immediately returns to ingress; it never awaits a worker. The processing job stores the `EventEnvelope` itself, so scheduler/worker/result derivation has no legacy-event cast. Long-poll readers own a dedicated pool, queue writers own another, and the durable event/execution/lease pool is separately bounded by `AGENT_DATABASE_POOL_MAX`; a parked PGMQ read must never starve durable commits. `startScheduler` is the sole worker dispatcher: it starts exactly `AGENT_MAX_THREADS` durable-job claim lanes, matching the bounded worker-pool capacity. Each lane atomically claims a job and renews processing/execution leases at one third of the execution lease, independently of idle wakeup latency. A duplicate claim and its `(transactionKey, replyChannel)` recipient registration run in one SQL statement; reclaim is payload-hash guarded, so a conflict cannot take an expired execution lease. An active transaction collision joins the durable owner without a second dispatch or retry budget consumption; its terminal success or failure is derived and delivered once to every registered channel. Result identity is `result:<transactionKey>:<replyChannel>`; retry exhaustion uses `processing-failed:<jobEventId>:<replyChannel>`, so neither can occupy another recipient's terminal identity. Results use the single durable PGMQ result queue; `channel` is the envelope/WebSocket routing key, not a physical PGMQ queue name. Expired execution claims remain reclaimable and are never converted to a result-less terminal row. `src/server/delivery` claims each result with a durable lease of `AGENT_DELIVERY_LEASE_SECONDS`; each claim has an attempt ID, and only its owner can mark delivered after result-queue publication and best-effort live hub projection. Worker completion is recorded before egress, and egress errors never rewrite that terminal execution state. `src/server/execution` stores the transaction-key claim. `src/server/metrics` holds aggregate counters plus ingress active handoffs, scheduler backlog age, expired lease count, and active dispatches behind `GET /metrics`; it never exposes payloads or identifiers. `src/server/worker` owns a lazy bounded Worker Thread pool and the worker action allow-list; no worker is created for an empty queue.

`src/server/transport/websocket` accepts only parsed channel protocol frames. On subscribe it captures a durable per-stream high-water vector, registers a replaying subscriber, sends cursor-to-high-water history, flushes buffered post-high-water events, then enables live delivery. The cursor is persisted only after each socket send callback succeeds, preserving at-least-once replay across disconnects. `src/server/event-store/store.ts#replayChannels` joins the high-water stream vector inside PostgreSQL under `event_store_stream_channel_sequence_idx`, so it reads only each stream's requested sequence range rather than loading a channel's complete history into the process. `src/server/stream/mailbox` isolates each connection: its bounded queue drops only progress/control under pressure and closes that connection when durable traffic cannot be retained.

`agent_events` is frozen. The consumer no longer writes it, `event_store` is the only append target, and the table is kept read-only for rows written before the canonical store existed. Phase 7 of the [Agent Renewal plan](../../../agentRenewal.md) drops it.
