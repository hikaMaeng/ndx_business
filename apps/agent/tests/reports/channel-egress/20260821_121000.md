# Cursor reconnect replay report

## Scenario

1. Connected a WebSocket client and subscribed to the single-stream test channel `replay.test`; retained the `subscribed.cursor` token.
2. Disconnected the client.
3. Submitted one `hash.sha256` request whose reply channel was `replay.test`.
4. Reconnected with the retained cursor and the same channel fingerprint.

## Result

The reconnect received exactly one canonical `hash.sha256.result` event for the offline transaction, addressed to `replay.test`. The first subscription yielded a nonempty opaque cursor. The exact queue message and rows for `replay-1787249186736` were removed after observation.

`agent.results` spans more streams than the protocol's 128-stream cursor limit in this long-lived development database. That broad cursor subscription is deliberately rejected rather than producing an oversized token; this report therefore uses a bounded single-stream subscription.
