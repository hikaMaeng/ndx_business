# Test Report: event-store delivery and precision

## Timestamp

2026-08-20 00:22 (local)

## Deployed target

`npm run deploy agent` completed with `/health` HTTP 200 on `127.0.0.1:18081`.

## Executed proof

1. Sent the exact same PGMQ source event ID twice (`acceptance-delivery-once-002`).
2. Measured `pgmq.q_agent_results` before and after delivery.
3. Queried `event_store`, `event_delivery`, and every stream counter.
4. Queried `/metrics` without and with the configured bearer token.
5. Ran the WebSocket browser scenario and headless smoke test.

## Results

- Result-queue delta: `1` for two identical source deliveries.
- Source event: one row at sequence `1`; its result is sequence `2` with the
  source event as `causation_event_id`.
- Delivery row: `attempts=1`, `delivered_at IS NOT NULL`.
- Counter query (`last_sequence < max(event_store.sequence)` or missing): `0`.
- `event.persisted` logs sequence as JSON string (`"sequence":"1"`), preserving
  PostgreSQL bigint precision.
- `/metrics`: unauthenticated `401`; token-authenticated `200` with aggregate counters.
- WebSocket scenario: passed. Headless smoke: passed.

## Failures

None against the plan. A later review of this build found two defects outside its scope: a
`completeExecution` failure leaked the visibility timer and stranded the message, and a held
delivery lease acknowledged its source without sending. Both are fixed and covered in
`apps/agent/tests/reports/delivery-invariants/20260820_014800.md`.

## Reproducibility

`npm run deploy agent`, then send the same source event ID to `agent_requests` twice and re-run the
`event_store`, `event_delivery`, and stream-counter queries.
`docker exec admin psql -U postgres -d ndx_business` reaches the database.
