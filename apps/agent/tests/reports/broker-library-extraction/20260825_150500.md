## Executed Steps

### 1. 빌드

`npm run build` — 4 task 성공. 산출물 크기:

```
apps/agent/dist/server/index.js   1.5mb
apps/agent/dist/server/worker.js  4.2kb
```

첫 시도에서 `worker.js`가 **1.4mb**로 나왔다. `worker-entry.ts`가 broker barrel(`agent_domain/broker`)을 import해 `pg`·`express`·`ws`까지 번들에 끌어온 것이다. `agent_domain/broker/worker` subpath와 `src/broker/worker/index.ts` barrel을 추가해 4.2kb로 잘랐다. 계획의 "10KB 미만" 기대치는 이 수정 뒤에 충족됐다.

subpath 추가 직후 한 번 더 실패했다. esbuild `--alias:agent_domain=...dist`가 `agent_domain/broker/worker`를 디렉터리로 치환하는데 그 안에 `index.js`가 없었다. barrel 파일을 만들어 해결.

새로 뜬 warn 1건: `wire-outside-protocol status=warn detail=5 wire types in common but outside common/protocol`. 해당 5개는 아래와 같다.

| 타입 | 위치 | 판단 |
| --- | --- | --- |
| `DatabasePoolSnapshot` | `broker/database.ts` | 오탐. pg 풀 카운터 |
| `EventQueueMessage` | `broker/queue/transport.ts` | 오탐. PGMQ 행 shape |
| `StreamEvent` | `broker/stream/hub.ts` | 오탐. `EventEnvelope` 별칭 |
| `ResultPayload` | `broker/idempotency/store.ts` | 경계. DB jsonb이자 result payload |
| `MetricsSnapshot` | `broker/metrics/registry.ts` | **실제 wire 계약**. `/metrics`로 노출되고 부하 하네스가 소비 |

이 타입들은 이동 전과 글자 하나 다르지 않다. 검사 스크립트가 `packages/*/src`만 훑기 때문에 `apps/`에 있을 때는 보이지 않던 기존 부채가 드러난 것이다. warn이며 violation이 아니므로 이번 범위에서 고치지 않았다. `MetricsSnapshot`을 `common/protocol`로 올리는 것은 metrics wire 계약을 새로 설계하는 별도 결정이다.

### 8. 브라우저

`http://localhost:18081` 로드 → 접근성 트리에서 `stream · online` 확인 → WS 연결됨.

먼저 UI의 `Send to agent` 버튼을 눌렀다. DB에는 `session.create.request` command와 `session.create.request.result`가 정상 기록됐으나 화면 타임라인은 비어 있었다. 폼 제출로 페이지가 다시 로드되며 인메모리 모델이 초기화된 것으로, 전송 자체는 성공했다. `apps/agent/src/front`는 이번 리팩터에서 수정하지 않았으므로 이동으로 생긴 결함이 아니다. 다만 **미해결 관측**으로 남긴다(§Failures).

broker가 담당하는 구간만 분리 검증하기 위해 페이지를 새로 로드한 뒤 서버에서 이벤트를 밀어 넣었다.

```
POST /api/events {"action":"hash.sha256","payload":{"input":"ws-projection-probe"},"transactionKey":"ws-probe-1"}
```

브라우저 화면:

```
INBOUND  # agent.results  hash.sha256.result  DELIVERED
{ "ok": true, "value": "16c90ecec45dd45dea06d11e3ee9f51a241b1b592726eb6b6f6f99bcb848c566" }
tx ws-probe-1…
```

HTTP ingress → PGMQ → Worker → outbox → result queue → Router → gateway queue → hub → mailbox → socket 전 구간이 브라우저까지 도달했다. 콘솔 오류 없음.

검증 뒤 probe 행은 모두 삭제했고 두 ledger 잔여는 0/0이다.

## Failures

이번 리팩터로 인한 실패는 없다. 다만 세 가지를 정직하게 남긴다.

1. **`admin_domain` 단위 테스트 1건 실패** — `organization snapshot parser validates appearance tokens` (`packages/admin_domain/src/common/index.test.ts:40`). `git status --porcelain -- packages/admin_domain`이 비어 있어 이번 작업에서 건드리지 않았음이 확인되며, 순수 파서 로직 테스트라 agent 파일 이동과 무관하다. **기존 `master`의 결함**이며 범위 밖이라 고치지 않았다.
2. **UI 폼 제출 시 타임라인 초기화** — §8 참조. front 소스 미수정, broker 무관. 별도 조사 필요.
3. **`wire-outside-protocol` warn 5건** — §4 참조. 이동 전과 동일한 타입이며 violation 아님.
